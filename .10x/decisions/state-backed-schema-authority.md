# State-backed schema authority

## Context

`cdf.lock` currently combines facts with incompatible lifecycles: governed output schema,
contract hashes, compiler and dependency tuples, source configuration, semantic pins, destination
capability sheets, and compiled-artifact identity. It is simultaneously treated as committed
expectation authority, first-use publication output, contract registry, and promotion commit point.
That makes environment-specific schema authority a project-filesystem concern and leaves promotion
with a recoverable gap between a lockfile CAS and state-ledger publication.

CDF already has backend-neutral checkpoint, fenced-lease, and promotion-settlement contracts plus
a durable SQLite state implementation. The user ratified replacing the file authority rather than
moving the overloaded `LockedResource` object wholesale into a database. CDF is customer-zero and
unreleased, so the replacement is current-only: there is no lockfile reader, migration, alias,
dual authority, or deprecation period.

This decision also supersedes only the conflicting lockfile, automatic `evolve|freeze`, global
quarantine switch, and removed-command clauses in the still-active project/manifest, portable
execution, discovery, file-source, contract/type, semantic registry, destination receipt,
observability, onboarding, conformance, demo, roadmap, and book-coverage records. Their unrelated
resource layout, compiler, source I/O, type fidelity, package, receipt, checkpoint, rendering, and
test requirements remain active. The focused replacement specifications below are the behavioral
authority for every superseded clause; S5 owns removing stale product/docs text after code cutover.

## Decision

### Identity and ownership

`cdf.toml` MUST contain a stable typed `[project].id`, generated by `cdf init` and preserved when a
project moves between machines. The schema-authority key is:

```text
state authority domain + project id + environment + resource id
```

The store owns its stable authority-domain identity. A fencing token or generation from another
domain is never comparable. Project name is presentation, not identity. Resolved secret values
never participate in the key and never enter state, plans, manifests, packages, or diagnostics.

### Schema versions and heads

CDF state owns immutable content-identified logical schema versions and one active head per key.
A head carries an exact schema hash and monotonically increasing generation. Versions carry their
canonical Arrow schema, predecessor, bounded discovery-evidence reference when available,
creation time, and provenance. A head may be `active` or fenced `promoting`; corrupt or missing
version material behind a head fails closed.

Backend-neutral schema-authority types and traits belong in `cdf-kernel`, beside checkpoint and
lease contracts. SQLite implements them now. No generic implementation crate or Postgres backend
is introduced until a second concrete store exists.

Logical schema authority is separate from target installation. State may record, per destination
and target, the installed logical version, physical fingerprint, capability-sheet hash, and last
verified receipt/checkpoint. A destination's physical schema is observed and reconciled but never
becomes canonical CDF schema authority.

### First use and ordinary preparation

There is no unlocked evolving steady state. Authority is absent, or an immutable active version
exists.

- `cdf plan` is no-write. With absent authority it may perform bounded observation, compile one
  exact proposed baseline and admission program, and render or export that proposal.
- Ordinary `cdf compile` may establish an absent baseline in state and publish derived local
  artifacts. `cdf compile --locked` requires an existing active head.
- Ordinary `cdf run` may establish absent baselines. It MUST prepare every selected resource first,
  then atomically establish the complete selected set before any package, destination, receipt,
  checkpoint, or run-ledger mutation. A conflicting CAS executes nothing.
- `cdf run --locked` requires existing active heads and cannot establish first-use authority.
- Once a head exists, plan, compile, and run enforce it. They may observe source schema but cannot
  widen governed output, add discovered destination columns, or advance the head.

Compiled artifacts remain immutable derived cache under `.cdf/compiled/`; `.cdf/manifest.json`
remains a generated resource index. They bind the exact relevant state key, authority-domain id,
head generation, schema hash, authored inputs, compiler/runtime identities, and native plans. They
do not become schema authority. `.cdf/schemas/` may retain verified cache copies but is not
authoritative.

### Portable plans

Portable plans bind a per-resource state precondition, never a global store revision:

- `absent` plus the complete proposed immutable version; or
- exact authority domain, key, head generation, and schema hash.

Whole-plan preflight verifies every relevant key and all existing source, destination, checkpoint,
input, and host preconditions before effects. An unrelated resource or environment change does not
invalidate the plan. Preflight cannot repair, rediscover, reinterpret, or accept drift.

### Drift and promotion

Automatic `Evolve | Freeze` output behavior is deleted. Every established schema is fixed;
compiled admission policy chooses a total field-, row-, record-, or partition-level disposition:
safe variant capture, safe quarantine, or run failure. Missing nullable fields remain typed null;
lossless coercion is allowed only when compiled policy permits it. Required progress, CDC
operation, transaction, or other unsafe control violations fail when quarantine cannot preserve
correct advancement.

`cdf schema promote RESOURCE` is the only operation that may advance an established head. It is
dry-plan by default and exact execution under `--execute`. Promotion uses a state-backed
reader/writer settlement barrier: ordinary runs acquire a short generation-bound settlement permit
immediately before destination mutation; promotion fences new permits, drains earlier permits,
settles verified corrections/rematerialization, and atomically publishes the new active head plus
publication history in one state transaction. A stale executor cannot commit after publication.

Initial promotion supports top-level lossless reconciliation only. There is no automatic,
future-only, nested, or partially reconciled promotion, and no raw residual value storage in state.
Exact values remain in verified packages or verified destination readback.

### Trust presets

The current trust labels remain, with these ratified defaults:

- Experimental captures safely isolatable field drift as `_cdf_variant` and fails other
  violations.
- Governed captures safe field drift, quarantines safely isolated row/record/partition violations,
  and fails control or unsafe framing violations.
- Financial fails every violation except compiled lossless coercion and missing-nullable typed-null
  materialization.
- Serving captures safe field drift, quarantines safely isolated violations, fails control or
  unsafe violations, and retains its separately governed sampled fast path.

Policy serialization uses total typed dispositions. The global `quarantine.enabled` switch is
deleted. PII redaction moves to shared evidence policy because variant and quarantine evidence
share the privacy boundary.

### Product deletion

`cdf.lock` is deleted outright. `cdf inspect lock`, `cdf contract freeze`, and lock-backed
`cdf contract test` are deleted. `cdf contract show` remains a project-free policy rendering
command. There is no initial schema export/import surface; that is a separately ratified future
GitOps capability.

Generic crash-safe project-file publication remains only for authored/generated project files that
still need it. Lock-last publication and lock-specific CAS/guard behavior are removed with their
only authority file.

## Alternatives Considered

### Move `LockedResource` into SQLite

Rejected. It preserves the lifecycle error and makes source configuration, compiler tuples,
destination sheets, and cache identity part of live schema state.

### Slim `cdf.lock` to schema only

Rejected. A project-local file still cannot provide environment-scoped shared authority or atomic
promotion publication across a fleet.

### Use destination schema as authority

Rejected. Destinations have different physical mappings and may drift independently; logical Arrow
meaning must remain destination-neutral.

### Key shared state by project name or global revision

Rejected. Names collide and global revisions make unrelated work invalidate exact selected plans.

### Preserve `Evolve` for ordinary runs

Rejected. It allows source observation to change output and DDL without an explicit schema epoch,
which is precisely the surprising behavior this decision removes.

### Add Postgres and schema export/import now

Rejected. SQLite proves the stable backend-neutral contract. Postgres and GitOps artifacts are
separate implementations/products, not prerequisites for removing the wrong local authority.

## Consequences

- Every run has one exact logical schema version before effects.
- Dev and prod may observe different source instances without fighting over a filesystem artifact.
- Portable plans survive unrelated state changes and become naturally fleet-executable when hosts
  share one authority domain.
- Promotion publication becomes state-atomic, while destination settlement remains receipt-gated
  and resumable rather than pretending to be distributed 2PC.
- The lockfile parser/model, lock CAS, lock hydration, lock-bound artifacts, contract registry,
  inspection/report fields, fixtures, docs, and diagnostics become deletion work.
- A required project id changes the current project grammar and scaffold. Because the product has
  not shipped, missing ids are invalid rather than inferred or migrated.
- The cutover is intentionally large but removes two authorities, several impossible policy
  combinations, and the user's circular compile/lock workflow instead of adding another layer.
